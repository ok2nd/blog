開発は「Google Gemini」を使った。プログラム作成では「Claude」が優秀だが、1日に使えるメッセージ（？）制限がある。何回も手直しが必要になるような一定の規模以上のプログラム作成には使えない。「Google Gemini」は、無料枠でも制限は無さそう。

「Google Gemini」の無料枠内で、今回のようなある程度の規模のアプリケーションが出来るか不安だったが、期待した程度のものはできた。

【仕様概略】

● PHPとMySQLを使う。

● シンプルなカレンダー＆スケジューラ。時間などは入れない。日付単位のスケジュール管理。スケジュール項目の数種類の色分けが出来る。

● データベースは1つのシンプルなテーブルを使う。

CREATE TABLE IF NOT EXISTS tbl_schedule (
    id_schedule INT(10) UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    id_account VARCHAR(20) NOT NULL,
    c_date DATETIME NOT NULL,
    c_date2 DATETIME,
    c_color VARCHAR(20) NOT NULL,
    c_memo VARCHAR(256) NOT NULL,
    c_delete INT(10) UNSIGNED,
    c_registtime DATETIME  NOT NULL
) CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;

● 1か月単位のカレンダーを表示。初期値は当月。クエリパラメータで、id=ユーザーアカウント指定。id=ユーザーアカウントは年月やスケジュールインプット画面にも全てのPHP画面に引き継がれる。パスワードやログインは使わない。

● 前月、翌月移動ボタンと当月ボタンが必要。移動後のURLには、クエリパラメータでy=年&m=月表示。

● カレンダーの日付空白部分をクリックしたら、ポップアップウインドウで、スケジュール入力画面を出す。
日付：クリックした日付を表示（変更可とする）
日付2：スケジュール最終日（変更可とする）
色：ラジオボタンで、赤、ピンク、オレンジ、青、緑、紫、グレー（初期値）
件名：テキストエリア（スケジュール内容：日本語可）
登録ボタン：押したら、データベースにスケジュールが入力される。
id_accountには、id=ユーザーアカウントを入れる。
c_deleteは0にする。
c_registtimeにタイムスタンプを入れる。

● スケジュールが登録されたら、該当の日付にスケジュール表示する。指定した色で文字全体の背景色として、文字は白色とする。<td>枠内の横一杯に広がるように表示する。

● スケジュールは、クエリパラメータのid=ユーザーアカウントのものだけを表示する。

● 日付2（c_date2）があるデータは、<td>を跨ってスケジュール表示する。（※ これは実現が難しく断念。）

● 既存のスケジュールをクリックすると、スケジュール入力画面と同様の修正画面が出る。「修正」ボタンと「削除」ボタンを表示。

● 「削除」ボタン実行時には、c_deleteに「999」を入れる。

● カレンダー表示で、c_delete=999のデータは除外する。

● 「Holidays JP API (日本の祝日API)」を使って、祝日表示する。
　　https://holidays-jp.github.io/api/v1/date.json

以上の要求仕様で、ほぼ期待通りのものが出来上がった。データベースはテーブル構造を示しただけで、MySQLへのアクセス方法については、何も指示していない。修正依頼は、大半が細かいデザインに関すること。

プログラムコードファイルは、以下の4つ。コメントや空白行を含んで、合計1,000ステップほど。

  • config.php（60ステップ）
  • index.php（620ステップ）
  • schedule_form.php（340ステップ）
  • process_schedule.php（120ステップ）

「Google Gemini」は、レスポンスも速いし、何度でも修正要求に応えてくれる。この程度の規模のアプリが、アバウトな要求仕様で、無料で出来てしまうのは驚き。
