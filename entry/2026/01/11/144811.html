今回、「Forge（Stable Diffusion WebUI Forge）」でなく、「ComfyUI」を使ってみる。

■ 使うPCのスペック

画像生成AIをローカルで行うPCとしては最低限レベル。

CPU インテル Core i5-14500T (14コア(6P+8E)/1.7GHz)
GPU NVIDIA GeForce RTX 3050 LP 6GB
メモリー 32GB
ストレージ 1TB M.2 SSD PCI Express x4対応（Gen4対応）
OS Windows 11 Pro 64bit

■ モデル構成：Qwen-Image-Edit-2511

2025年末にリリースされた「Qwen-Image-Edit-2511」。

  • 従来のQwen-Imageよりも実写の肌の質感やライティングが大幅に向上。
  • 「Qwen2.5-VL」を視覚セマンティック制御に使用しており、プロンプトへの忠実度が極めて高い。
  • 単なる画像編集だけでなく、リライティング（照明変更）や高精度なインペイントにも対応。

※ 結果的には、「Qwen-Image-Edit-2511」では、以下のローカル画像生成AIに比べて、高画質は得られなかった。

  • Stability Matrix＋Forge＋「FLUX FP8版」
  • Stability Matrix＋Forge＋「FLUX.1[dev] GGUF版」
  • Stability Matrix＋Forge＋「FLUX.1[schnell] GGUF版」

PC構成（VRAM 6GB）を考慮し、以下の軽量化版を組み合わせる。

コンポーネント おすすめのバージョン 役割
Diffusion Model qwen-image-edit-2511-Q4_K_M.gguf 生成のメインエンジン。GGUF版でVRAMを節約。
CLIP / Vision qwen_2.5_vl_7b_fp8_scaled 画像理解とプロンプト解釈。
VAE qwen_image_vae 画像のデコード・エンコード。
LoRA Qwen-Image-Edit-Lightning 必須。 これにより4〜8ステップでの超高速・高画質生成が可能に。

---【実際にやった手順】---

■ パッケージ追加

Stability Matrixの「パッケージ」から ComfyUI をインストール。

■ 「ComfyUI-Manager」を入れる

  • Stability Matrixで「Launch」をクリックして「ComfyUI」を起動する。
  • Stability Matrixで「To see the GUI go to: http://127.0.0.1:8188」と出たら、ブラウザで、http://127.0.0.1:8188を開く。
    ※ Stability MatrixのComfyUI設定（歯車アイコン）の中の
    Auto-Launch「--auto-launch」チェックボックスをオンにしておくとブラウザで自動的に開くようになる。
  • 「ComfyUI-Manager」が「Extensions」で見つからなかった。
  • 「ComfyUI-Manager-main.zip」をダウンロード 

    https://github.com/ltdrdata/ComfyUI-Manager/archive/refs/heads/main.zip

  • zipを展開したフォルダー「ComfyUI-Manager-main」を、
    「Stability Matrix\Data\Packages\ComfyUI\custom_nodes」の下に入れる。
  • 一度ComfyUIを閉じ（Stability MatrixでStop）、再度「Launch」。

■ 必要なカスタムノードのインストール

  • 「🧩 Manager」 ボタンをクリック。

  • メニュー内の 「Custom Nodes Manager」 をクリック。

  • 右上の検索窓に GGUF と入力し、リストに出てくる ComfyUI-GGUF を探して右側の「Install」を押す。

  • 同様に Qwen と検索し、もし ComfyUI-Video-Post-Process や ComfyUI-QwenVL があればインストールしておくと、実写生成の幅が広がる。
    ※ ComfyUI-Video-Post-Processは見つからなかった。
  • インストールが終わると「Restart required」と出るので、Stability Matrixで一回Stopして再度Launch（再起動）。

■ モデルファイルの配置

  • モデル「qwen-image-edit-2511-Q4_K_M.gguf」を以下からダウンロード。
    https://huggingface.co/unsloth/Qwen-Image-Edit-2511-GGUF/tree/main
    置き場所：Data/Models/unet

■ 組み合わせる「必須パーツ」

モデル単体では動かないため、以下の3点も用意。

  • Text Encoder (Visionモデル):
    ファイル: qwen_2.5_vl_7b_fp8_scaled.safetensors

    https://huggingface.co/Comfy-Org/Qwen-Image_ComfyUI/blob/main/split_files/text_encoders/qwen_2.5_vl_7b_fp8_scaled.safetensors

    置き場所: Data/Models/clip

  • VAE:
    ファイル: qwen_image_vae.safetensors

    https://huggingface.co/Comfy-Org/Qwen-Image_ComfyUI/blob/main/split_files/vae/qwen_image_vae.safetensors

    置き場所: Data/Models/vae

  • Lightning LoRA (超高速化用):
    これを併用すると、たった4ステップで画像が完成。
    ファイル: Qwen-Image-Edit-2511-Lightning-4steps-V1.0-bf16.safetensors

    https://huggingface.co/lightx2v/Qwen-Image-Edit-2511-Lightning/blob/main/Qwen-Image-Edit-2511-Lightning-4steps-V1.0-bf16.safetensors

    置き場所: Data/Models/lora

■ ComfyUI 内部での設定（GGUFを認識させる）

まず、GGUF形式のモデルを読み込めるようにする。

ComfyUIを起動（Launch） 。

画面上部の 「🧩 Manager」 をクリックし、「Custom Nodes Manager」 を開く。

検索窓に GGUF と入力し、「ComfyUI-GGUF」 がインストールされているか確認。

■ 実写生成ワークフローの組み立て

真っ黒な画面をダブルクリックして検索窓を出し、以下の順にノードを呼び出して配置してください。

● モデルの読み込み (Unet / CLIP / VAE)

「Unet-Loader (GGUF)」: unet_name で qwen-image-edit-2511-Q4_K_M.gguf を選択。

「DualCLIPLoader」: clip_name1 に qwen_2.5_vl_7b_fp8_scaled.safetensors を選択。

※ DualCLIPLoaderはGGUF形式 のCLIP専用の読み込みノードであるためFP8に合わないため、使わない。以下で通常のCLIPLoaderに変更。

「VAELoader」: qwen_image_vae.safetensors を選択。

● Lightning LoRAの適用 (高速化の肝)

「LoraLoader」: lora_name で Qwen-Image-Edit-2511-Lightning... を選択。

  • strength_model: 1.0
  • strength_clip: 1.0

■ 配置すべき「必須ノード」

今の画面には「画像を作るエンジン（サンプラー）」がまだない状態。画面の空いている場所をダブルクリックして、以下を追加。

KSampler (または KSampler (Advanced))

設定値を以下に変える。

  • steps: 4 （Lightning LoRAを使うため、4回で実写になる）
  • cfg: 1.0 （1.5以上にすると画像が焼けたように崩れる）
  • sampler_name: euler
  • scheduler: simple または sgm_uniform
  • denoise: 1.0

■ 「CLIP Text Encode」ノード

画面の空いている場所をダブルクリック。入力欄に clip text と入力。

候補に出てくる CLIP Text Encode (Prompt) を選択。

これを2つ（ポジティブ用とネガティブ用）作成。

■ 「VAE Decode」ノード

画面の何もないところをダブルクリック。

入力欄に vae decode と入力。

候補リスト VAE Decode を選択。

■ 「Empty Latent Image」ノード

画面の何もないところをダブルクリック。

入力欄に empty と入力。

候補リスト Empty Latent Image を選択。

■ 「Save Image」ノード

画面の何もないところをダブルクリック。

入力欄に saveと入力。

候補リスト Save Imag を選択。

■ 「CLIPLoader」の出し方

※ 「DualCLIPLoader」を使わず、一般的な「CLIPLoader」を使う。

画面の空いている場所を ダブルクリック。

出てきた検索窓に CLIPLoader と入力。

※「Dual」や「GGUF」が付いていない「CLIPを読み込む」を選択。

■ ノードの「線」を繋ぐ（パズルの完成）

各ノードの右側にある丸（●）から、左側の丸へドラッグして線を繋ぐ。

  1. メインモデルの接続: Unet Loader (GGUF) の「モデル」から LoRAを読み込む の「モデル」へ繋ぐ。
  2. CLIPの接続: CLIPを読み込む の「CLIP」から LoRAを読み込む の「クリップ」へ繋ぐ。
  3. プロンプトの接続: LoRAを読み込む の「CLIP」から、2つの CLIPテキストエンコード の「クリップ」へそれぞれ繋ぐ。
  4. サンプラーへの接続:
    • LoRAを読み込む の「モデル」から Kサンプラー の「モデル」へ繋ぐ。
    • 各 CLIPテキストエンコード から Kサンプラー の「ポジティブ」「ネガティブ」へ繋ぐ。
    • 空の潜在画像 から Kサンプラー の「潜在画像」へ繋ぐ。
  5. 画像の出力: Kサンプラー の「潜在」から VAEデコード を経由し、最終的に 画像を保存 へ繋ぐ。
  6. VAEの接続: VAEを読み込む から VAEデコード の「vae」へ直接繋ぐ。

■ 現在の状態を保存

画面左上の 「保存」 で現在の状態を保存。

保存先：Data/Packages/ComfyUI/user/default/workflows
